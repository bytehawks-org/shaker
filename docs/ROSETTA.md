# Rosetta: one parameter, every dialect

A parameter is declared **once** in Distillery (`runtime.env` of the package) and compiled into
`<bundle>/rosetta.map`. Shaker reads only that file and translates every way a value can arrive
into one canonical environment variable `BH_<PACKAGE>_<NAME>`.

```
container / pod :  --port=8081    BH_NGINX_PORT=8081    NGINX_HTTP_PORT_NUMBER=8081    BH_NGINX_PORT_FILE=/run/...
legacy server   :  /opt/bytehawks/etc/nginx/nginx.conf       server.port=8081   (and nginx.conf.d/*.conf)
                                      │
                                      ▼   shaker env / init / run
                          BH_NGINX_PORT=8081   (+ native_env twin, if declared)
```

## Map format

One parameter per line, `|` separated, `#` comments (generated by Distillery, but hand-writable):

```
env|type|default|flags|aliases|file_key|cli|native_env|description
BH_NGINX_PORT|port|8080||NGINX_HTTP_PORT_NUMBER|server.port|--port||HTTP listen port
BH_PG_PASSWORD|secret||required|POSTGRESQL_PASSWORD,POSTGRES_PASSWORD|auth.password|--password|PGPASSWORD|Superuser password
```

| Column | Meaning |
|---|---|
| `env` | canonical name, must match `[A-Za-z_][A-Za-z0-9_]*`; Distillery enforces the `BH_<PACKAGE>_` prefix |
| `type` | `string`, `secret`, `int`, `uint`, `port` (1-65535), `bool`, `path`, `enum:a,b,c` |
| `default` | applied when nothing else provides a value; empty = no default |
| `flags` | `required` → resolution fails when no source provides a value |
| `aliases` | comma list of other environment names accepted as input (upstream dialects, e.g. Bitnami); each also supports `_FILE` |
| `file_key` | key in configuration files (`section.key` for ini/json/yaml); the canonical name is also accepted as a key |
| `cli` | flag accepted on the command line; `--flag=value` or `--flag value`; a `bool` accepts the bare flag |
| `native_env` | extra variable exported with the same value - what the application itself reads |
| `description` | shown by `shaker env <pkg> --help-vars` |

## Precedence

| # | Source | `explain` label |
|---|---|---|
| 1 | CLI flag | `cli` |
| 2 | canonical env var | `env` |
| 3 | canonical `<ENV>_FILE` (content of the file, one trailing newline removed) | `env-file` |
| 4 | alias env var, then alias `_FILE`, in declaration order | `alias:NAME` / `alias-file:NAME` |
| 5 | configuration file key, then drop-ins (later wins) | `config:KEY` |
| 6 | default | `default` |

* `ENV` and `ENV_FILE` set together is an **error** (ambiguity is refused, not guessed).
* Empty environment variables count as unset.
* Containers normally use 1-4 and 6; legacy hosts 5 and 6; both can mix (an env var overrides the file,
  which makes hot-fixing a host or a one-off `docker run -e` trivial and visible in `explain`).

## Validation

Performed after resolution, all errors reported together, nothing is exported if any fails:

* `required` without value · unknown CLI flag · missing value for a flag
* type check (`port=99999`, `enum` value not listed, non-integer for `int`)
* both `ENV` and `ENV_FILE` · unreadable `_FILE`
* `bool` values are normalized: `yes y 1 true on` → `true`; `no n 0 false off none` → `false`.

## Provenance

```console
$ NGINX_HTTP_PORT_NUMBER=9000 shaker env nginx --server-name=example.com --format=explain
BH_NGINX_PORT                    alias:NGINX_HTTP_PORT_NUMBER 9000
BH_NGINX_WORKER_PROCESSES        default                      auto
BH_NGINX_SERVER_NAME             cli                          example.com
BH_NGINX_SERVER_TOKENS           default                      off
```

Secrets (`type secret` or names containing `PASSWORD`, `SECRET`, `TOKEN`, `_KEY`, `CREDENTIAL`) are
shown as `********`. Debug logging masks them too.

## Legacy configuration files

Discovery order for package `<pkg>` (first existing wins):

1. `--config=FILE` or `BH_SHAKER_CONFIG`
2. `$BH_ETC/<pkg>/<pkg>.{conf,env,ini,yaml,yml,json}`   (`/opt/bytehawks/etc/<pkg>/`)
3. `/etc/bytehawks/<pkg>/<pkg>.{conf,env,ini,yaml,yml,json}`

Drop-ins: for the chosen file `F`, every `F.d/*.conf` in lexical order, parsed as `KEY=VALUE`, later wins
(`nginx.conf.d/10-site.conf`, `99-local.conf`).

| Extension | Format | Notes | Needs |
|---|---|---|---|
| `.conf` `.env` `.cfg` (anything else) | `KEY=VALUE` | optional `export `, `#` comments, single/double quotes stripped, **no expansion** | - |
| `.ini` | `[section]` + `key = value` | flattened to `section.key`; keys before a section stay plain; full-line `#`/`;` comments | - |
| `.json` | any depth | scalars flattened to `a.b.0`; booleans `true`/`false` | `jq` or `python3` |
| `.yaml` `.yml` | any depth | same flattening | `python3`+PyYAML, or `yq` (mikefarah or python-yq) |

`BH_SHAKER_CONFIG_FORMAT=env|ini|json|yaml` overrides the extension. Limits: scalar values on one line;
no variable expansion or includes. On minimal images, have Distillery/CI pre-flatten JSON/YAML into
`KEY=VALUE` so the target needs no extra tool. Files are **parsed, never sourced**.

Example `nginx.conf` (ini style, `/opt/bytehawks/etc/nginx/nginx.ini`):

```ini
[server]
port = 8081
worker_processes = 4
name = example.com
[logging]
access_log = /var/log/nginx/access.log
```

## From parameters to native configuration

Rosetta produces environment; applications often need a native file. `shaker init` renders the
package templates (`runtime.templates`) with the resolved parameters; `shaker render` does the same
for any file:

```
worker_processes {{ BH_NGINX_WORKER_PROCESSES }};
server_name {{ BH_NGINX_SERVER_NAME:-_ }};
prefix {{ BH_PKG_PREFIX }};
```

Values are inserted verbatim (no escaping, no evaluation, `&`/`\` safe). A variable that is unset and
has no default fails the render and nothing is written.

## Writing a map by hand (without Distillery)

Any directory with a `rosetta.map` works: `shaker env myapp --map=./rosetta.map --format=dotenv` or
`shaker exec myapp --map=./rosetta.map -- /usr/bin/myapp`. This is the lightest way to give an
off-the-shelf distro package a normalized parameter interface.
