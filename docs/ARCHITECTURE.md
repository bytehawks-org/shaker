# Shaker architecture

Shaker applies, at install time and at runtime, what Distillery declares at build time.
It is the replacement for the hand-written per-application scripts of the Bitnami images
(`libos.sh`, `libfs.sh`, `libfile.sh`, `<app>-env.sh`, `setup.sh`, `entrypoint.sh`, ...).

## Filesystem layout (shared with Distillery)

```
/opt/bytehawks            BH_ROOT   real path. Binaries must never embed /opt/bh (RPATH, configs).
/opt/bh -> /opt/bytehawks BH_LINK   convenience symlink, created by `shaker bootstrap`
/opt/bytehawks/core       BH_CORE   core/shaker and core/distillery (this repository)
/opt/bytehawks/deps       BH_DEPS   libraries built by Distillery
/opt/bytehawks/etc/<pkg>  BH_ETC    configuration for legacy hosts (<pkg>.conf + <pkg>.conf.d/*.conf)
/opt/bytehawks/var        BH_VAR    state (var/lib/shaker) and logs
/opt/bytehawks/<pkg>      application prefix; <pkg>/.bytehawks/ holds the Distillery bundle
```

Reserved package names: `core`, `deps`, `etc`, `var`. Every path can be overridden with the
`BH_*` variables, and Shaker locates its own files from the script location, so it can live anywhere.

## Distro-agnostic by design

Shaker does not require any Bytehawks package. Rules enforced in the code and by CI on
Debian, Fedora, Rocky, openSUSE, Arch and Alpine:

* Only bash >= 4.2 and POSIX tools; no `realpath`, `sed -i`, `date %N`, `grep -P`, `envsubst`.
* No systemd needed: deployment type falls back to markers, cgroups and DMI.
* Package management goes through `pkg_*` (apt, dnf, microdnf, yum, tdnf, zypper, apk, pacman)
  with logical names resolved by `share/pkgmap.map`; the same code manages host packages and
  prepares Bytehawks ones.
* Optional tools (`jq`, `python3`, `yq`) are used only for JSON/YAML configuration files.
  Distillery can pre-flatten them so a minimal image needs nothing.

## Command surface

| Command | Container | Legacy VM/server |
|---|---|---|
| `shaker detect` | selects defaults | same |
| `shaker exec <pkg> -- cmd` | ENTRYPOINT: env/CLI/`*_FILE` -> canonical env -> exec | `ExecStart=` wrapper reading `/opt/bh/etc/<pkg>` |
| `shaker env <pkg> --format=dotenv` | debugging, `--env-file` | `EnvironmentFile=` for systemd |
| `shaker render tpl dest` | native config from env | same |
| `shaker hooks dir` | `docker-entrypoint-initdb.d` equivalent | same |
| `shaker pkg ...` | image build | provisioning |

See `ROSETTA.md` for the parameter model.

## Bitnami feature map

| Bitnami | Shaker |
|---|---|
| `liblog.sh`, `BITNAMI_DEBUG` | `log.libsh`, `BH_SHAKER_DEBUG`, `BH_SHAKER_LOG_LEVEL` |
| `libvalidations.sh` | `validate.libsh` (typed validation) |
| `libos.sh` users, `run_as_user` | `fs.libsh` |
| `libfs.sh` permissions, g+rwX/gid 0 | `fs.libsh` `configure_permissions_ownership` |
| `libfile.sh`, `render-template` | `file.libsh` |
| `libnet.sh`, `wait-for-port` | `net.libsh` |
| `*_FILE` secrets | Rosetta |
| `<app>-env.sh` | Rosetta map generated by Distillery |
| init hooks | `hook.libsh` |
| `libservice.sh`, persistence, nss_wrapper | planned (roadmap phases 4-6) |
